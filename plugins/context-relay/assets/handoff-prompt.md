You are writing a handoff: a note that lets a fresh conversation, with no memory of this one, continue the work without losing anything. Write it in the language the person has been using. Be concrete: name files, commands, decisions and numbers; do not describe the conversation, describe the state of the work.

Answer with Markdown in exactly this structure and nothing else:

# Handoff

## Goal
What the person is trying to achieve, in one or two sentences.

## Current state
What is done and verified, what is done but not verified, what is half-done. Mention the branch and whether there are uncommitted changes if you know.

## Decisions made
Each decision with its reason, one bullet per decision. Include decisions the person made explicitly and conventions that emerged.

## Files changed or important
Paths with one line each on what they hold or what changed.

## Open tasks and next step
The ordered list of what remains, the very next step first and precise enough to start on immediately.

## Gotchas
Traps, failed approaches, environment quirks, things that looked right but were wrong. If there are none, write "None noted".
