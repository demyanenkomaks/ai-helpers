# context-relay: дизайн

Статус: согласован 2026-10-19, не реализован. Этот документ является
контрактом, по которому пишется мод; меняйте его раньше, чем поведение.

## В одну строку

Погода контекста, подогрев кэша промпта и передача беседы в новый чат одной
кнопкой. Один мод, одна строка над промптом.

## Истоки

- Погодные полосы, показания и бары последних ходов взяты из примера Anthropic
  `token-weather` в `anthropics/claude-code-playground`
  (`claude-code/mods/token-weather`, Apache-2.0).
- Таймер кэша, лимиты, стоимость и субагенты сделаны по образцу
  `token-weather-usage` от augiefra (`augiefra/claude-mods`, Apache-2.0).
- Оба служат референсами; код пишется заново под API этой сборки. Всё
  скопированное хранит LICENSE и NOTICE в папке мода.

## Решения

### Измерение

- Мера: **абсолютные токены**, не проценты: `context.tokens` из
  `$.session.usage()` (входные токены последнего ответа, с кэшем; то же, что
  `total_input_tokens` статусной строки). Снимаем на `session.start`,
  `turn.complete` (только основной цикл) и `session.compact`.
- Без масштабирования под окно модели. На модели с окном 200k полоса не дойдёт
  до «Грозы», автокомпакт Claude Code сработает раньше; принято.
- Качество агента падает с длиной входа (Chroma, «Context Rot», 2025); полосы
  кодируют практическое правило «держаться ниже ~300k».

### Погодные полосы (4)

| Полоса | Токены | Глиф (терминал) | Иконка (десктоп) | Цвет |
| --- | --- | --- | --- | --- |
| Ясно | < 100k | ☀ | солнце | зелёный |
| Пасмурно | 100k–250k | ☁ | облако | жёлтый |
| Дождь | 250k–350k | 🌧 | дождевое облако | оранжевый |
| Гроза | ≥ 350k | ⛈ | грозовое облако | красный |

Границы задаёт настройка `bands` (три числа). Шкала зелёный → красный читается
без слов.

### Строка над промптом

Всегда компактно, одна строка:

```
⛈ 362k · 🔥 41m · 👥 1/3 · ⇄
```

- иконка погоды + токены (красная точка после токенов, пока любой лимит выше
  90%)
- 🔥 минуты до остывания кэша, красное «остыл» после
- 👥 субагенты: работает/всего; иконка красная, пока кто-то работает, иначе
  серая
- ⇄ кнопка передачи: только иконка, без подписи и подсказки, видна всегда. С
  «Дождя» окрашивается в цвет полосы.

Карточка по наведению (десктоп) / развёрнутый вид (терминал): окно модели,
токены последних ходов барами (12 последних, относительно самого большого),
лимиты 5 ч и 7 ч со временем сброса, стоимость сессии и доля последнего
запроса, пинги подогрева за этот простой и примерная цена одного пинга, список
субагентов с именами и длительностью.

Хук рисует свою строку и пропускает цепочку дальше (`next(e)`), поэтому другие
моды над промптом рисуются ниже.

Тост: один раз при входе в «Грозу», не повторяется, пока полоса не опустится и
не поднимется снова.

### Подогрев кэша промпта

- Таймер от начала последнего запроса основного цикла; TTL на этом плане 1 час
  (определяем как augiefra: по трафику, затем `CLAUDE_CODE_PROMPT_CACHE_TTL`,
  по умолчанию 1 ч).
- **Пинг**: `$.model.fork({ prompt: "Reply with the single word OK." })`, один
  вопрос без инструментов поверх транскрипта, обслуживается из кэша, в беседу не
  попадает.
- Автоподогрев: пока сессия простаивает, пинг на **55-й минуте** после
  последнего запроса (запас на сеть и неточность TTL), затем каждые 55 минут,
  остановка после заданного числа часов. Любое сообщение пользователя само
  обновляет кэш и перезапускает цепочку.
- Ручной пинг: небольшой элемент рядом с таймером 🔥.
- Пинги расходуют пятичасовой лимит и стоят чтение кэша всего контекста;
  карточка показывает число пингов и оценку цены одного.
- Настройка `warm`: список `выкл / 2 ч / 4 ч / 8 ч`, по умолчанию `4 ч`.

### Передача (кнопка ⇄)

Основной сценарий, целиком внутри мода:

1. Спросить модель поверх кэшированного транскрипта (`$.model.fork`) сводку по
   `templates/handoff.md`: цель, текущее состояние, принятые решения,
   изменённые файлы, открытые задачи и следующий шаг, подводные камни.
2. Записать в `~/.claude/context-relay/handoff/<проект>/<гггг-мм-дд-ччмм>.md`
   и указатель в `$.store`.
3. Выполнить `/clear` через `$.command.run`.
4. При перечитывании `prompt.context`, которое вызывает `/clear`, подложить
   сводку блоком в первое сообщение; показать одну строку «Контекст загружен из
   сводки <время>».
5. Удалить файл после доставки блока (не раньше).

Второй сценарий (новая сессия открыта руками): на `session.start`, если для
проекта есть сводка моложе 7 дней и ещё не доставленная, показать тост с
кнопкой **Загрузить**; без нажатия ничего не подкладывается. Невостребованные
сводки удаляются через 7 дней.

Хранение локальное, у пользователя (не в проекте, без обмена); обмен делается
позже отдельной правкой мода, если понадобится.

### Автоматика

- Триггер: `turn.complete` основного цикла при `context.tokens ≥ autoHandoffAt`
  (по умолчанию **500000**; `0` выключает).
- Перед очисткой: панель-диалог с **отсчётом 30 секунд** (настройка
  `countdownSeconds`) и кнопками **Сейчас** / **Отмена**. Отмена откладывает
  автоматику до следующего пересечения порога.
- Посреди хода не срабатывает: команды и так ждут простоя сессии.

### Субагенты

За сессию: работает / завершено / всего, по `agent.spawn` и `turn.complete`
цикла субагента. Список по наведению с именами и длительностью.

### Язык

- Без настройки. Поверхность `desktop`: системная культура читается один раз
  на `session.start` (Windows `Get-Culture`, иначе `LANG`/`LC_ALL`); `ru*`
  даёт русские подписи, остальное английские.
- Поверхность `terminal`: всегда английский.

### Поверхности

Десктоп в приоритете (ежедневная поверхность автора); терминал полностью
поддерживается и тестируется исполнителем (глифы и цвета, без SVG и наведения).

### Настройки (`userConfig`, Claude Code показывает их в `/config`)

| Ключ | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `warm` | список `off/2h/4h/8h` | `4h` | часов простоя держать кэш тёплым |
| `autoHandoffAt` | число (токены) | `500000` | порог автоматики, 0 выключает |
| `countdownSeconds` | число | `30` | время на отмену перед автоочисткой |
| `bands` | три числа | `100000, 250000, 350000` | границы полос |
| `handoffDir` | путь | `~/.claude/context-relay/handoff` | где лежат файлы сводок |

### Состояние

Всё, что читает отрисовка, живёт в `$.state` по контракту в
`types/index.d.ts` (показания, таймер кэша, субагенты, ожидающая сводка);
межсессионные факты (указатель на сводку, выученный TTL) в `$.store`.
Переменные модуля не хранят ничего, что потеряет перезагрузка.

## Вне первой версии

Обмен сводками через проект, масштабирование полос под окно, запись в
статусную строку, звуки, учёт токенов по субагентам.

## Риски, проверить при реализации

- Обслуживается ли `$.model.fork` из кэша после долгого простоя (если нет,
  пинг всё равно согреет кэш ценой одного полного чтения).
- Поднимается ли `prompt.context` после `/clear`, вызванного плагином, в
  сессии десктоп-приложения так же, как в терминале.
- Карточки по наведению на десктопе для дерева AbovePrompt (augiefra их
  рисует, значит примитивы есть).
